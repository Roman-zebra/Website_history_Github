# Public GitHub and protected paid assets — T8 design constraint

The repository is public. [GitHub says public repository content is accessible to everyone](https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories). A Worker gate around `/api/paid/*` **cannot protect plaintext files committed to GitHub** or plain static assets copied into `dist/`; visitors can fetch those files from GitHub or a direct static URL. The current `wrangler.jsonc` sends `/api/*` through the Worker first, while other matching assets are served directly. The existing plan's phrase “store paid data in the repository and have the Worker restrict delivery” needs the following concrete implementation before any paid asset is committed.

## Free-tier candidate for T8

1. Keep final paid geometry, texture and audio payloads **encrypted at rest** in the public repository as independently authenticated chunks. No plaintext paid payload, source that reconstructs it, or encryption key may be committed. Public static delivery of ciphertext is acceptable. The GitHub main → Cloudflare Workers Builds pipeline copies only ciphertext to `dist/` without needing a build-time secret, preserving the user-selected publishing path.
2. Generate a random content key locally and provision the same key as a [Cloudflare Worker secret](https://developers.cloudflare.com/workers/configuration/secrets/) during T8. Do not print the key in logs, browser storage or Git. The frontend never receives it. Each chunk uses a unique AES-GCM nonce and authenticated metadata. Keep a versioned manifest of chunk IDs, content type, plain size and hashes so stale caches and tampering fail closed.
3. A Worker `/api/paid/chunk/:id` handler checks a license before calling `env.ASSETS.fetch()` for the encrypted chunk, decrypts it with [Workers Web Crypto AES-GCM](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/), and returns only that chunk. The browser receives plaintext only after a successful check; post-delivery copying is outside the project's protection goal. Keep the static `/paid-cipher/*` route serving ciphertext only.
4. Design chunks for the [Workers Free limits](https://developers.cloudflare.com/workers/platform/limits/): 10 ms CPU per HTTP invocation, 128 MB memory, 100,000 Worker requests per day, 25 MiB maximum per static asset and 20,000 static files per version. Start with about 1 MiB of ciphertext per request; benchmark actual decryption and license lookup locally and on the free deployment before choosing a final chunk size. Do not assume a whole 25 MiB model can be decrypted within 10 ms. One request per tiny mesh fragment would also waste the daily request allowance.
5. Configure the paid API route under `run_worker_first`, use the existing `ASSETS` binding for the ciphertext fetch, and return `Cache-Control: private, no-store` for decrypted responses. [Cloudflare's static asset binding documentation](https://developers.cloudflare.com/workers/static-assets/binding/) explains that matched assets otherwise bypass the Worker by default and that `env.ASSETS.fetch()` can retrieve an asset inside a Worker.

This is a design checkpoint, not a finished payment system. T8 still needs the signed Stripe webhook, license storage and restoration, secret provisioning, unauthorized-direct-URL and tamper tests, and a free-plan CPU/request benchmark. If the benchmark fails, adjust chunk size or simplify delivery before considering a paid service. The user has authorized only no-cost development and test-mode integration at this stage.
