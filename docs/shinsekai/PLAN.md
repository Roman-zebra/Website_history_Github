## 1. 何を作るか
| 内容 | 価格（案） | 中身 |
|---|---|---|

| 本編の解放（同じページで購入） | ¥800 | 塔の中（エレベーター・展望台）、ロープウェイ、白塔、ルナパークと新世界の全域、全部の建物の中、年代の切替、遊び全部 |

- 地図サイト（今の Japan Time Atlas）は無料のまま。

体験の中身：
- 舞台：1912〜1923年の新世界（北半分＝塔から放射状の街路、南半分＝ルナパーク）と初代の塔。
- 年代：1903（第五回内国勧業博覧会の跡地）→ 1912 開業 → 1923 ルナパーク閉園 → 1943 塔の解体 → 1947 空中写真 → 今。遊べる中心は 1912〜1923。
- 遊び方：歩く・走る・乗る（ロープウェイ、塔のエレベーター、園内の乗り物、路面電車）、建物に入る、夜のイルミネーション、写真モード、ミニゲーム（射的など当時の遊び）、絵葉書集め（見つけると保護期間満了の本物の絵葉書と解説が見られる）、謎解き（消えた塔・消えた遊園地・ケーブルカーの行き先）。
- 表現：人は出さない（無人の「記憶の街」。1943年に塔が消えたことを夢でたどる導入と合う）。色は推定で全部に付けて完成した見た目にする。推定の根拠は `colors.json` と台帳に残し、ゲーム内の「考証モード」で推定部分を確かめられるようにする。

## 3. 画質と速さの目標
ブラウザで GTA6 と同じ処理は不可能なので、「見た目の水準」を次の手段で狙う：物理ベースの光、濃い空気感、密度の高い小物、色の作り込み。人を出さない分の処理を光・材質・小物に回す。

| 段階 | 想定の機械 | 目標 | 主な効果 |
|---|---|---|---|
| Ultra | RTX 3060 級 | 1440p 60fps | 全部入り（下記） |
| High | GTX 1660 SUPER（このPC） | 1080p 60fps | SSR と被写界深度を軽く |
| Medium | ノートの内蔵GPU（Iris Xe・M1） | 60fps（動的解像度） | 焼き込み照明中心、影は近くだけ |
| Low | iPhone 12／Pixel 6a 級 | 60fps（動的解像度） | 焼き込み照明のみ |

技術の決め事（Codex が実装。変える時は理由を codex-progress.md に書く）：
- 描画：three.js の WebGPURenderer（WebGL2 へ自動で切替）。最新安定版を `vendor/three-rXXX/` に置き、既存の leaflet と同じく PROVENANCE.json を付ける。ビルドは今の方式（バンドラー無し）を保つ。
- 光：物理ベースの空（時刻・季節）、太陽のカスケード影、空からの環境光。建物は Blender（このPCの GPU）でライトマップと AO を焼く。夜は電球を数千個＝光る板＋ブルーム、近くの数十個だけ本物の光源（タイル／クラスター方式）。
- 後処理：TAA、GTAO、SSR（雨の路面・池）、高さフォグと光の筋、ブルーム、トーンマップ（AgX）、LUT で色調整、フィルムグレイン、写真モードだけ被写界深度。
- 材質：PBR。テクスチャは KTX2（Basis）、形は glTF＋meshopt。汎用素材は CC0（ambientCG、Poly Haven）、出典は台帳へ。色は推定で全部に付ける（§1）。
- 密度：石・電柱と電線・幟・提灯・看板・植え込み・車両を GPU インスタンス描画。遠くは板ポリ（インポスター）。区画ごとの遅延読み込み（無料区画と有料区画に分ける、§5）。
- 1912年の大阪らしさ：「煙の都」の霞、電線だらけの空、幟と暖簾、夜の電飾（詳細は調査で確定）。
- 予算：無料エリアの初回読み込み 20MB 以下（残りは歩きながら読む）、全域 400MB 以下、描画命令 Ultra 1,500／Low 300 以下が目安。

## 4. 再現する「動くもの」と建物の中（全部）
下は調査前の見出し。確定版は Codex が `docs/shinsekai/GIMMICKS.md` に作り、Claude が出典と照合して「確認済み／推定」を付ける。人は出さない。
- 塔：エレベーター（昇降機）、展望台、夜の電飾の点滅、白塔へのロープウェイ（客車の往復）。
- ルナパーク：白塔（ホワイトタワー）、園内の乗り物（回転木馬ほか、調査で見つかった全部）、演芸場（幕・照明・書き割りが動く）、活動写真（映写機が回り、保護期間満了の映画を映す）、楽隊（音だけ）、噴水・人工の滝、花壇、イルミネーション、門と切符売り場。
- 街：路面電車（阪堺電車・市電、要確認。運転台は暗くする）、置かれた人力車・自転車・荷車、風に揺れる幟・暖簾・提灯、屋台の湯気、煙突の煙、電線の揺れ。
- 建物の中（軍艦島と同じく入れる）：塔（切符売り場・エレベーター・展望台）、白塔、演芸場、活動写真館、食堂・カフェ、射的場、旅館など。中の動き（映写機と幕、舞台の仕掛け、厨房の湯気、射的の的が倒れる など）。
- 時間と天気：昼・夕・夜、晴・雨（濡れた路面の反射）。季節は開業の7月が基本。

## 5. 課金とマップの広がり（決済は Stripe）
- マップを区画に分け、無料区画（塔の周り）と有料区画（それ以外の全部）を最初（T4）から分けて作る。
- 購入するとその場で有料区画の読み込みが始まり、当時らしい仕切り（工事中の板囲い・柵・霧など）が開いて先へ進める。塔の入口も購入で開く。
- 決済の流れ：Stripe Checkout（Stripe の購入画面）→ Stripe から Cloudflare の Worker へ購入完了の知らせ（Webhook、署名を確認）→ Worker が購入を記録し、解放用の鍵（ライセンスキー）を発行 → ブラウザに保存して有料区画を開く。
- 有料区画のデータは Worker で購入を確かめた人にだけ配る（URL を直接開いても取れない）。ブラウザに届いた後のコピーまでは防げないので、そこは目標にしない。
- 購入の復元（別の端末・ブラウザ）：購入完了画面と領収メールに出すライセンスキーを入力。
- まずテストモードで作る。Stripe のアカウント作成と秘密鍵の設定（wrangler secret）はあなたが行う。Claude と Codex は本物の鍵を扱わない。
- 税（消費税・海外の付加価値税など）の扱いは M5 の前にあなたが確認する（Stripe Tax は有料の追加機能なので v3.3 で候補から外した）。

## 7. 使う場所と受け渡し（衝突しない仕組み）

GitHub に書き込むのは Codex だけにする（書き手を1人にして衝突を無くす）。
**完成したサイトは GitHub 経由で動かす（v3.2）**：main への push → Cloudflare Workers Builds（既存の `japan-then-and-now`、各コミットに成功の記録あり）が `node scripts/build.cjs` を実行して公開する。このPCのファイル・ツールは制作と確認のためだけに使い、公開サイトはこのPCに依存させない。公開に要るもの（3D データ・テクスチャ・音など）は全部リポジトリに入れる（GitHub は1ファイル 100MB まで、Cloudflare の静的アセットは1ファイル 25MiB まで）。有料区画のデータも同じ経路で配り、Worker が購入を確かめてから返す。

## 9. 止まっても・途中で指示が入っても、やり直しにならない仕組み
- 現在地を常にファイルに残す：Codex は `docs/shinsekai/codex-state.json`（status・current・next・updatedAt）と TASKS.md、Claude は `STATE.md`。
- 途中の指示は「差分」として扱う：①指示ログに追記（Claude は INSTRUCTIONS-LOG.md、Codex は codex-progress.md の「指示ログ」）→ ②影響するタスクだけ書き換え → ③今の作業の区切りから続行。済んだ調査・取得は台帳を見て二度やらない。
- Codex はリポジトリのルートの AGENTS.md に新世界の節を置き、どのセッションでも最初に state を読む。
- 作業用クローン（repo\）は消さずに使い続ける（毎回ダウンロードし直さない）。
- 使用上限で止まったら：Claude はこのセッション内の定期ジョブ（30分ごと）で、上限が戻り次第 STATE.md の続きから再開する。やることが無くなったらジョブを消す。Codex は CODEX-PROMPT.md の「再開用」を貼るだけで続きから。

## 10. 使用量（API）の節約ルール
1. 調べた結果は台帳に1回だけ記録し、取り直さない（取る前に台帳を検索）。
2. ブラウザは文字の抽出を優先。スクリーンショットは縮小して必要な時だけ。操作はまとめて1回で送る。
3. テストは関門で1回だけ。途中は対象を絞ったテストのみ。見た目の確認も関門で1回。
4. 長い資料は要点をファイルに残し、次からは要点だけ読む。長い会話は区切りで新しい会話に替え、state ファイルから再開する。
5. Codex は GPT-6 Sol（High）が基本。Astra は難所だけ。Ultra（並列サブエージェント）は使わない。
6. Claude は Opus 5.5。推論は通常 High、資料の食い違いの判定など難しい所だけ Max（切替はあなたが画面で行う。Claude からお願いする）。
7. Claude は Codex ができる作業をしない（重複を無くす）。
8. 仕様を先に決め、実装はまとめて行う（行ったり来たりの修正を減らす）。
9. 課金が要る項目（有料プラン、支払い方法の登録が要る機能、有料の素材・映像・フォント・音・API、追加の使用量など）が出たら、その作業を止めて課金しない安全な方法を探す。見つからなければあなたに相談する（v3.3）。
